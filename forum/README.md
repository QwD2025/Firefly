# LINELOG

2030 年的虚构世界只读论坛。1998 年创立。首页、版块、历史档案、搜索和主题页共用同一组公开内容。

## 本地运行

在本目录执行 `npm install`，再执行 `npm run dev` 预览或 `npm run build` 生成 `dist/`。`npm run preview` 可以预览构建产物。

## 自己写帖子

1. 在 VS Code 复制本目录的 [发帖模板.txt](发帖模板.txt)，粘贴到 [帖子/](帖子/) 文件夹，重命名为自己的文件名，例如 `旧车站.txt`。一个文件就是一整个主题。文件名用于网址，可以用中文、字母、数字，以及词之间的短横线或下划线。发布后改标题可以沿用原链接。
2. 填写标题、分区、作者和时间。分区填「茶馆」「重要通知」「资源分享」中的一个。作者直接填显示昵称；时间按北京时间填写，例如 `2001-01-28 22:41`，年份范围为 1998–2030。留一行空白，再写正文，按普通文本换行分段。
3. 从单独一行的 `【回帖】` 开始，每块写一条评论。复制整块即可增加评论；只发主帖时，删掉模板里的所有回帖块。时间按先后排列，楼层自动编号，主帖为一楼。`引用：2` 会链接到二楼，普通评论可以省略这一行。
4. 保存。在 VS Code「源代码管理」选择 `Firefly`，暂存帖子文件，填提交说明，点「提交」，再点「同步更改」。Cloudflare 构建成功后，帖子会出现在所选分区、首帖年份档案和站内标题搜索中。以后添评论，直接修改同一文件，再提交、同步。

写到一半可以把文件留在「帖子」文件夹以外。发布目录只读取直接放入其中的 `.txt` 文件；模板本身不会出现在网站上。构建遇到格式错误会指出文件名和原因。

## 内容约定

- `src/data/site.ts` 是建站年份、站内年份与版块的配置入口。档案年份从这里生成。
- `content/forum.json` 登记公开账号与主题元数据。账号字段为 `id` 和 `name`，主题字段为 `id`、`board` 和 `title`。
- `content/posts/` 收录已审核的 Markdown。每份文件包含 `topic`、`author`、`number`、`postedAt`，可选 `editedAt` 和 `replyTo`。日期采用带时区的 ISO 8601 格式，主题内楼层从 1 连续编号。
- 世界事实、角色知情记录、未批准草稿和交接上下文留在私有创作区。网站只使用本目录的公开数据。
- 仓库中的构建与发布配置使用本目录的 `dist/`。GitHub Pages 分支发布需手动触发，域名和图床由现有托管服务管理。
